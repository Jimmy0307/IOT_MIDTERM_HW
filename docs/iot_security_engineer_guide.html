1｜先畫系統，再談攻擊

使用者 → HTTPS 入口 / 反向代理 → 應用程式 ├→ IoT 服務 → 裝置（命令路徑 E2） └→ PostgreSQL（資料路徑 E3） 區域網路上的 victim ↔ gateway：E1 研究 L2 路徑與 TLS

安全邊界是資料、權限或信任假設改變的位置。資料庫不是每個裝置命令都必經。先問：資產是什麼？攻擊者位在哪裡？能觀察或修改什麼？什麼情況算成功？控制放在哪一層？

實驗攻擊者能力要保護的性質
E1同一 L2 網段發送偽造 ARP網路路徑、傳輸機密性
E2持有一筆合法請求，可重送或修改訊息真實性與新鮮度
E3能提供搜尋輸入程式碼與資料分離、資料庫權限
工程師的問法：「攻擊者能否重送已簽章的 DISPENSE 命令？」比「API 有沒有加密？」更接近可測試的威脅。

2｜Ethernet、IP 與 ARP

應用資料 → TCP segment → IP packet → Ethernet frame ↓ 目的 IP 不變，下一跳 MAC 隨每一跳改變

交換器以 MAC 表轉送乙太網路框架；IP 選路決定下一跳。ARP 在 IPv4 區域網路把下一跳 IP 對應到 MAC。ARP 缺少內建身分驗證，主機可能接受偽造的對應並更新快取。

正常：Victim 的 ARP：gateway IP → Gateway MAC 中毒：Victim 的 ARP：gateway IP → Attacker MAC Victim → Attacker → Gateway → Attacker → Victim

只有 ARP 映射改變，不代表成功攔截。若攻擊者不轉送，流量可能中斷，這是 disruption / DoS；要稱 MITM，還須證明流量經過攻擊者且服務持續。雙向路徑、交換器學習行為、ARP 快取和轉送設定都會影響結果。

實驗對照：baseline gateway MAC 4a:0f:22:2d:9b:4a；中毒後為 attacker MAC 46:ca:02:a9:48:20。這是特定 run 的值，不是固定應寫入程式的值。

防禦：分段、DHCP snooping 搭配 Dynamic ARP Inspection、靜態綁定與監測可降低風險；需檢查交換器信任埠、靜態 IP 例外及誤封風險。本實驗中這些是概念控制。

3｜TLS：保護內容，也要驗證對方

Client ─ ClientHello ─→ Server Client ← 憑證鏈 / 握手 ─ Server Client 驗證：信任鏈 + 主機名稱 + 有效期限 + 用途 雙方協商金鑰 → 加密且完整性保護的應用資料

TLS 1.3 使用握手協商密鑰，完成後以 AEAD 同時保護資料機密性與完整性。憑證驗證把「我連到某個會講 TLS 的伺服器」提升為「此伺服器擁有受信任憑證，且名稱符合目標」。受信任 CA、SAN 名稱、有效期限和憑證鏈缺一不可；撤銷檢查則依客戶端設定與環境而定。

例：攻擊者控制 L2，HTTP 封包可見示範 token；HTTPS 的攻擊者端 PCAP 看不到該明文，victim 仍收到有效回應。這支持此實驗中的傳輸保護，不能推論端點永不洩密。
curl 60 / HTTP 000：未信任的 CA 使 TLS 握手驗證失敗；000 表示沒有取得 HTTP 回應，不是 HTTP 成功。不要用 -k 當成安全修復。

TLS 不阻止 ARP 偽造，也不保證可用性。TLS 終止於反向代理時，代理之後仍需依信任邊界設計內部傳輸與權限。

4｜HMAC、時間窗、nonce 與重放

Client：M = method | path | timestamp | nonce | body tag = HMAC-SHA256(device_secret, M) Server：驗證身分與 tag → 檢查時間窗 → 原子性消耗 nonce → 執行命令 重送相同 M + tag → nonce 已使用 → 拒絕

HMAC 用共享密鑰驗證完整性及持有密鑰者；它不提供加密，也不提供不可否認性。時間戳限制有效期間，但時間窗內仍可重放；nonce 的唯一性記錄補上這個缺口。實作必須定義簽章涵蓋的 method、path、timestamp、nonce 和精確 body bytes，避免兩端對序列化結果理解不同。驗證 tag 時使用常數時間比較。

例：第一次 DISPENSE 成功，action_count=1。相同請求再送一次：簽章仍正確，但 nonce 已消耗，應拒絕，action_count 仍為 1。若改 body 但沿用舊 tag，則簽章不匹配。

工程陷阱：先查 nonce 再分開寫入會產生競態；多副本需共享且原子化的去重儲存。nonce TTL 至少涵蓋接受時間窗與允許時鐘偏差。記憶體快取重啟會遺失狀態；裝置金鑰外洩則攻擊者可製作新合法簽章。

Idempotency 不同：nonce 防止安全重放；idempotency key 讓合法重試不重複產生副作用。支付、設備命令常需兩者共同設計。

5｜SQL 注入：別讓資料變成語法

不安全：字串拼接 → SQL parser 同時看到語法與使用者內容 安全：SQL 模板 + 參數 → 資料庫將輸入視為值 應用身分 → 資料庫角色 → 僅授權必要表格與操作

當輸入被插進 SQL 字串，資料中的引號與運算子可能改變查詢語意。參數化查詢將輸入和 SQL 結構分開；不要自行加引號或用字串格式化冒充參數化。表名、欄名和排序方向通常不能直接用值參數替代，應使用固定允許清單或資料庫驅動的識別字 API。

# 示意：使用驅動提供的參數介面
cursor.execute("SELECT * FROM devices WHERE name = %s", (name,))
# 不要："... WHERE name = '" + name + "'"
本實驗：一般查詢 1 筆；同樣的惡意輸入在 raw SQL 路徑得到 4 筆，在參數化路徑得到 0 筆；正常參數化查詢仍得 1 筆。限制角色的敏感表 SELECT、UPDATE、DROP 均被拒絕，資料列數前後 4→4。

參數化修復注入根因；least privilege 限制失陷後可讀寫的範圍，無法代替參數化。E3 runner 直接呼叫資料存取函式，沒有獨立評估 HTTP transport；不要把結果稱為實際擷取的 HTTP response。

6｜把觀察變成可信證據

假設 → baseline → 攻擊 / 控制 → 觀察 → 恢復回歸 → 判定 ↓ 原始 PCAP + 文字解讀 + result.json + manifest

一份 PCAP 是二進位封包紀錄，文字 dump 只是渲染；24-byte header 不代表捕獲到封包。檢查捕獲介面、時間、封包數、方向及過濾條件。交換式網路在攻擊前不一定把 victim↔gateway 單播送到 attacker，因此 baseline 在 victim 端捕獲；MITM 期間則在 attacker 端捕獲。

以 manifest 的 run ID 選擇最終證據，不以檔案修改時間選最新。SHA-256 可偵測位元組變更，但不能單獨證明來源真實或解讀正確。保留失敗 run 與捕獲限制，才能追溯。

判讀練習：HTTPS PCAP 未見 token，只能說此捕獲中未找到該明文；再結合有效回應、憑證驗證與正確捕獲位置，才有較完整的實驗支持。

7｜從實驗到工程現場

預防：TLS / HMAC / 參數化 ↓ 偵測：憑證失敗、nonce 重用、拒絕查詢、ARP 異常 ↓ 應變：隔離受影響節點 → 保全證據 → 輪替金鑰 → 驗證恢復

設計日誌時記錄時間、來源、裝置 ID、事件類型、關聯 ID 與結果；避免記錄明文金鑰與完整 token。讓時間同步、保存期限、存取權限及告警誤報率有明確負責人。僅有拒絕日誌不等於完整偵測與復原流程。

事件情境：多個裝置出現 nonce 重用。先確認是否為合法重試、時鐘偏差或客戶端 bug；再比對裝置 ID、時間與來源，保全證據，必要時撤銷該裝置密鑰並觀察新事件。不要因單一訊號就推論 TLS 已被破解。

安全發布應固定依賴版本、執行測試與機密掃描，檢查最小權限並保存產物雜湊。對外分享前亦需檢查 evidence 中的主機名稱與本機路徑是否適合公開。

8｜讓知識變成能力

基礎 → 協定 → 安全控制 → 證據判讀 → 系統設計 → 應變演練
  1. 基礎：能畫出 Ethernet、IP、TCP、DNS、HTTP 在一次請求中的角色，解釋封包經過路由器時哪些地址改變。
  2. 協定：用授權的隔離環境觀察 ARP、TCP 握手、TLS 連線；記錄捕獲點與限制。
  3. 控制：實作參數化查詢、每裝置金鑰與 nonce 去重；針對競態和時鐘偏差做測試。
  4. 證據：為每個主張列出 baseline、觀察、反例、原始檔案與不可推論的部分。
  5. 設計：對一個設備命令系統畫資料流與威脅模型，列出預防、偵測、限制影響與復原責任。

自我檢查

ARP 表改變就能證明 MITM 嗎？不能；還需證明流量經攻擊者轉送，且連線繼續。否則可能只是中斷。
簽章正確為何仍可能被拒絕？請求可能重用 nonce、超出時間窗，或裝置身分已撤銷。
TLS 有效時 HTTP 000 代表什麼？000 是 curl 未收到 HTTP 回應的占位值，必須結合 exit code 與握手日誌判斷；本實驗 exit 60 表示憑證驗證失敗。
為何最小權限不能取代參數化？攻擊仍可能讀取該角色被允許的資料；參數化才阻止輸入改變 SQL 語法。

進一步閱讀：RFC 826 ARP、RFC 8446 TLS 1.3、RFC 2104 HMAC、OWASP SQL Injection Prevention、PostgreSQL privileges。本手冊是學習路線，不代表閱讀完成即可取得工程師能力；需搭配實作、評審與事故演練。
